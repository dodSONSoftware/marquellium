# macOS release gates

M5 implementation is not by itself a signed release. The development bundle retains the compatibility identifier `com.markdownviewer.desktop` and app-data location. Never clear user recovery records to make a release test pass.

1. Preserve source fixtures and use isolated disposable app data for acceptance (`MARKDOWN_VIEWER_DATA_DIR`). Run `pnpm typecheck`, `pnpm test`, `cargo test --manifest-path src-tauri/Cargo.toml`, and Clippy with warnings denied.
2. Build normal Visual using `VITE_M3V_VISUAL_PROTOTYPE=0 pnpm build --bundles app`. Run `node scripts/check-workers.mjs`. Export the binding fixture to all formats and inspect content, pagination and protected fallbacks.
3. Run `python3 scripts/acceptance/m5-benchmark.py --runs 30 --output /private/tmp/m5-benchmark.json`. It uses disposable files and launches the native release app with `--m5-benchmark`. Input timing measures synchronous CodeMirror dispatch with a live Split preview; source hashes must remain unchanged. Fresh-process launch measurements run from the Python process launch through a native ready message after restored Split content and two animation frames. A separate native `run()`-entry clock includes restore/render but excludes the dynamic loader. OS caches are warm after the first run. This does **not** establish cold filesystem-cache behavior or physical keystroke-to-pixel latency. Retain raw samples; don't relabel narrower measurements as NFR acceptance.
4. Verify keyboard navigation/focus in Preferences, palette, exports, Find, Source and Visual drafts; test coordinated Quit/Cancel while a print preview is open. Confirm spell check enable/disable in actual WebKit. Full VoiceOver QA remains a separate human accessibility gate if no screen-reader test is recorded.
5. Before distribution, obtain a Developer ID Application identity and an existing notarization Keychain profile. No credentials are stored in the repo. `MARQUELLIUM_SIGN_IDENTITY='Developer ID Application: …' MARQUELLIUM_NOTARY_PROFILE='…' sh scripts/acceptance/sign-macos.sh` signs/notarizes/staples/verifies the app. This uploads the app to Apple only when explicitly run with credentials. The script fails before signing if prerequisites are absent.
6. Produce the final ZIP/DMG from the stapled app, hash it, and test installation/file association/Gatekeeper on a clean macOS account. Do not publish development/ad hoc bundles as notarized releases.

M6 owns real Windows/Linux installers, file association and native print acceptance. No macOS result proves platform parity. Offline core/network capture, cold-launch measurements and any remaining accessibility or P0/P1 acceptance gaps must remain explicit in the milestone report.

Current [release acceptance follow up](release-follow-up-2026-11-02.md) records the completed keyboard controls and Linux native Quit/Cancel, offline and export checks. It lists the remaining platform, signing and acceptance gates without changing historical evidence.
