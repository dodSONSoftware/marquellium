## Save defect and correction

The previous save implementation constructed `.<filename>.mdviewer-tmp-<pid>` and opened it with `File::create`. A pre-existing symlink at that name could redirect truncation and writing to an unrelated file. Saves to the same destination in the same process also shared that temporary name.

The implementation now exclusively creates a random temporary file in the destination directory. Its name is independent of the document filename. Rust owns its cleanup, preserves existing destination permissions, synchronizes it before committing, and checks the expected disk revision again. Existing targets use atomic replacement. New targets use persistence without clobbering an existing file. Newly created files inherit tempfile's private creation permissions.

The public Save and Save As entry points still use the registry's serialized canonical buffer and return the existing SaveError/SaveResult errors. The ordinary save path remains behind typed native commands.

Three new regressions exercise the production path.

- A symlink at the former predictable temporary name leaves its target and the symlink intact while saving the intended document.
- A nested save to the same destination succeeds independently. The outer save detects the changed revision and leaves the completed inner save intact.
- An injected writer writes three bytes, then returns StorageFull. The original file and revision stay intact, the error propagates, and the partial temporary file is removed.

Existing regressions continue to verify that an external edit during the temporary-write phase survives and a newly created Save As target cannot be overwritten.
